## 1. Current architecture

`agentsec` is a **layered, dependency-inward** offline harness. The import rules
are not prose — they are enforced by `tests/test_architecture.py`
(see §7). The flow of one run is:

```
task ─► cli.run ─► mvp.build_mvp_runner ─► ExperimentRunner.run(ExperimentConfig)
                                  │
        ┌─────────────────────────┼───────────────────────────────┐
        ▼                         ▼                               ▼
   Agent(model, gateway,     PolicyEngine                  TraceRecorder
   recorder)                 (flat rules, first-match)     (stamp→redact→
        │                                                    validate→append)
        │  messages                     │                          ▲
        ▼                               │                          │
   ModelAdapter (MockModel fixture)     │                          │
        │  ModelResponse.tool_calls     │                          │
        ▼                               ▼                          │
   ToolGateway.invoke(...) ── validate ─► policy.decide ─► execute tool ─► emit events
        │                                                                    │
        └──────────────────────── one JSONL trace ───────────────────────────┘
                                                                             ▼
                                              TraceEvaluator (read-only counts)
                                                                             ▼
                                     DeclarativeScenario.interpret → passed/failed/inconclusive
```

**Layer boundaries (enforced, `tests/test_architecture.py`).**

- `tools/` must not import `models/`; `policy/` must not import `tools/` or
  `trace/`.
- `agent.py` imports only abstractions: it must not import any concrete tool,
  `policy`, or `models.mock`.
- `eval/` must not import tools/policy/agent/gateway; it is a pure read-only
  analysis layer.
- `experiment/` (runner/config) must not import tools/policy/concrete tools;
  the runner only delegates.
- `scenarios/` must not execute anything (no `.invoke`, `.decide`, `.complete`,
  `.run`, `emit_event`, `write_event`).
- `cli.py` and `mvp.py` contain **no execution logic** (no `.complete`, `.invoke`,
  `.decide`, `while`, `ToolCall`, `ModelResponse`).
- `gateway.py` is the **only** module that calls a tool's `run`.
- No banned frameworks (`langchain`, `crewai`, `pandas`, `sqlite3`, `requests`,
  `flask`, `torch`, …) anywhere in `src/` or `tests/`.
- `experiment/` may not use `threading`, `multiprocessing`, `asyncio`,
  `concurrent.futures` or `subprocess` (single-run, sequential only).

**Composition root.** `src/agentsec/mvp.py` is the one place that wires the
deterministic stack (`MockModel` + sandbox tools + policy + recorder + `Agent` +
`TraceEvaluator` + `ExperimentRunner`). It *constructs* but never executes.

**Configuration.** `ExperimentConfig` (`src/agentsec/experiment/config.py`) is
composed, not copied: it embeds `AgentConfig` and carries `experiment_id`,
`task`, optional `trace_path`, optional `policy_path`, `mock_script`,
`sandbox_files`, `sandbox_db_writes`, `sandbox_db_seed`. It has **no** fields for
temperature, seed, retries, parallelism or credentials.

## 3. Current ToolGateway / tool-execution model

`ToolGateway` (`src/agentsec/tools/gateway.py`) is the **single mediated path**
for every tool call. Its lifecycle, per call:

1. look up the tool — `UnknownTool` if missing;
2. validate args against `ToolSchema.validate_args` — `ToolValidationError`, the
   tool is not reached;
3. emit `tool_requested` (with `args_hash` + redacted `args_redacted`);
4. `policy.decide(agent_id, tool, args, ctx, action=…, resource=…)`;
5. emit `policy_decision`;
6. `deny` → emit `tool_result{denied}` and return `DeniedResult`;
   `require_approval` → resolve approval (below); `allow` → execute;
7. emit `tool_executed`, run the tool, validate its output;
8. emit `tool_result` and return a structured `ToolResult`.

**Approval model (OD-2).** Deterministic and offline. `invoke` accepts
`approval=True` (granted) or `approval=False` (refused); when neither is given,
an optional scripted `approver` callable decides. If nothing grants approval the
call stays `pending_approval` and is **not** executed.

**Two invariants enforced by tests** (`tests/tools/test_no_bypass.py`,
`tests/tools/test_gateway.py`): a denied call **never** invokes the tool; a
`require_approval` call **never** silently becomes an allow.

**Tool contract.** A tool exposes a typed `ToolSchema` (name, description, JSON
Schema input/output), an `action(args)` / `resource(args)` pair used only for
authorization metadata, and `run(args, ctx)`. The gateway derives `action` and
`resource` from the tool and hands them to the policy engine, so the policy
engine never imports a concrete tool. Tools are built **only** through
`agentsec.tools.factory` (`TOOL_FACTORIES`); the factory is the only supported
way to obtain a gateway, and a gateway is the only supported way to execute a
tool.

**ToolResult status** is `ok` | `error` | `denied` | `pending_approval`; `ok`
and `executed` are distinct properties, so a caller can always tell *why*
nothing happened.

**Current tools.** `calculator` (AST walker; no `eval`/`exec`/names/strings/IO;
finite float output), `fs_sandbox` (memory-only; rejects `..`, absolute/drive/UNC
paths, null bytes, reserved device names; no symlinks; 64 KiB cap), `mock_db`
(in-memory; understands `SELECT`/`INSERT`/`UPDATE`/`DELETE`, single
`WHERE col = value`, `?` params; `read_only=True` by default; per-instance seed),
`mock_email` (memory-only sink; output carries no payload, only `sent`,
`recipient`, deterministic `msg-NNN` id).

**Sandbox boundary.** Tools enforce *containment* (a request cannot leave the
sandbox); **which** in-sandbox resource is allowed is a *policy* question.
`fs_sandbox.resource()` returns the **raw** requested path so policy can judge
scope, while the tool's own normalization/rejection happens later at run time.

## 4. Current trace model and schema

**One JSONL line = one event.** Every event carries the shared header
`schema_version` (`"1.0"`), `run_id`, `event_id` (`ev-<seq:06d>`),
`parent_event_id`, `seq`, `timestamp` (timezone-aware, normalized to UTC),
`agent_id`, `model`, `scenario`, `event_type`.

**Twelve event types** (`src/agentsec/trace/schema.py`, `TRACE_EVENT_TYPES`):

| # | Event | Per-type fields | Emitted by |
| --- | --- | --- | --- |
| 1 | `run_started` | `config_ref`, `scenario_id`, `seed`, `temperature` | agent |
| 2 | `agent_input` | `input_ref`, `task` | agent |
| 3 | `model_request` | `messages_hash`, `tool_specs_hash`, `temperature`, `seed` | agent |
| 4 | `model_response` | `response_hash`, `finish_reason`, `usage`, `latency_ms`, `text_ref` | agent |
| 5 | `tool_requested` | `tool_name`, `args_hash`, `args_redacted` | gateway |
| 6 | `policy_decision` | `decision`, `matched_rule`, `reason` | gateway |
| 7 | `tool_executed` | `tool_name`, `started_at` | gateway |
| 8 | `tool_result` | `ok`, `result_hash`, `error`, `side_effects` | gateway |
| 9 | `security_event` | `label`, `severity`, `evidence` | **never emitted** (see §8) |
| 10 | `agent_output` | `output_hash`, `answer_redacted` | agent |
| 11 | `run_completed` | `steps`, `duration_ms`, `usage_total` | agent |
| 12 | `run_failed` | `error_type`, `message` | agent |

The union is **discriminated on `event_type`**, so unknown types and missing
per-type fields are rejected by **both** pydantic and the generated JSON Schema
(`extra="forbid"` on every model).

**Schema artefacts.** `trace_json_schema()` normalizes the generated schema so
`event_type` is re-added to every variant's `required`. `scripts/export_trace_schema.py`
writes the same bytes to two copies — `schemas/trace/trace_event.v1.schema.json`
(the artefact `README.md` links) and the packaged
`src/agentsec/schemas/trace/trace_event.v1.schema.json` (read at runtime via
`importlib.resources`). Drift is caught by `tests/schema/test_schema_file.py`
and `tests/schema/test_packaged_schema.py` (the latter also checks the packaged
copy works outside the repository).

**Recorder.** `TraceRecorder` stamps the header, **redacts**, validates and
appends. `event_id` is `ev-<seq>` and the clock is injectable, so a run replayed
with a fixed clock is byte-identical. `security_event` is defined and exported
in the schema but **no runtime path emits it** — it is an unused extension point.

**Redaction.** `Redactor` replaces known secret patterns
(`openai_key`, `aws_key`, `bearer`, `lab_fake_secret`, `assigned_secret`) and
sensitive mapping keys with `[REDACTED:<kind>]`; it is deterministic and
idempotent and can hash values (`hash_value`, sha256). Redaction happens on the
write path, so no write bypasses it. It is explicitly **best-effort, not a DLP
system**.

## 6. What students can currently learn/do

**Commands** (all offline, no key, no network):

```bash
PYTHONPATH=src py -m agentsec run labs/LAB-0X-.../config.yaml   # one deterministic run → trace
PYTHONPATH=src py -m agentsec inspect runs/<run>/trace.jsonl    # event order + parent links
PYTHONPATH=src py -m agentsec evaluate runs/<run>/trace.jsonl   # read-only descriptive analysis
PYTHONPATH=src py -m agentsec labs check                        # 8/8 reproducibility check
```

Students can currently:

- run all eight labs and read the resulting JSONL trace;
- distinguish the **ten teaching distinctions** (`labs/README.md`), notably
  request ≠ execution, decision-before-execution, `deny` prevents execution,
  `require_approval` ≠ execution, `allow` + `tool_executed` = really ran,
  synthetic side effects, and a `tool_result` existing with no `tool_executed`;
- reconstruct the chain **task → response → request → policy → execution →
  result → answer** from `run_id`/`event_id`/`parent_event_id` alone;
- practice on 36 trace-reading exercises with an instructor answer key;
- follow event-by-event walkthroughs and use the instructor guide's rubric and
  discussion prompts;
- observe authorization-vs-necessity (LAB-06) and authorization-vs-
  confidentiality (LAB-07) without any injected instruction.

**Instructors** additionally get a teaching sequence, timings, marking rubric
and discussion prompts; **reviewers** get the architecture in
`docs/development.md`, the schema under `schemas/trace/`, the implementation and
the tests.

## 7. Existing limitations explicitly documented by the repository

These are stated *by the repository*, not inferred.

**Scope / claim limits (`README.md`, `docs/development.md`, `labs/README.md`).**

- Not a benchmark, scoring system or ranking; makes **no research-novelty
  claim**; claims **no security effectiveness**; makes no claim about real
  model/agent behaviour.
- The model is a **deterministic fixture, not an LLM**; repeated runs show
  determinism, not a distribution.
- No live model provider; `httpx` is an optional extra for an adapter that
  **does not exist**. No provider factory.
- No defences are implemented; the adversarial labs observe behaviour only.
- No memory, RAG or persistence; conversation state is an in-memory list.
- LAB-07 is authorized, synthetic, in-memory egress — **not** real exfiltration,
  a vulnerability demo or a propensity measurement.
- Redaction is best-effort and **not** a DLP system.
- The policy engine is a teaching model, not a production authorization system.
- Sandbox tools are safe **by construction** (no host fs/db/network), not by OS
  enforcement; `shell_sandbox` and real tools are out of scope.
- **Phase 17 is CLOSED** with a **NO-GO**; a documented *research implementation
  freeze* keeps the real stochastic adapter, provider factory, repeated-trial
  harness, research corpus, research metrics, research evaluator/schema
  extensions and the research benchmark **unimplemented**.

## 14. Proposed test strategy

Keep the existing discipline; add coverage for each new behaviour.

- **Stay hermetic and offline.** No network, no clock, no RNG; keep the fixed
  clock in `labs check`; keep `release_check.py` scratch-only (`mkdtemp`,
  `pytest -p no:cacheprovider`, mkdocs `-d <scratch>/site`).
- **Guards get their own tests.** Each metadata/CI change updates
  `tests/test_licensing.py` / `test_version.py` / `test_release_check.py` and the
  manifest together; the release-gate tests stay hermetic via the injected
  `FakeRunner`, and a new test asserts the emitted warning set equals the
  documented set (B5).
- **Architecture invariants stay enforced** by `tests/test_architecture.py`;
  new modules must satisfy the existing import rules or the rules are explicitly
  revised (never silently relaxed).
- **Labs stay covered** by `tests/labs/test_lab0*.py` (config↔scenario equality,
  expected observations) plus `agentsec labs check` in CI.
- **Schema drift stays covered** by `tests/schema/test_schema_file.py` and
  `test_packaged_schema.py`; regenerate with `export_trace_schema.py` whenever
  the schema changes.
- **New quality gates (B4, D1)** run in CI; the coverage floor is introduced at
  or just below the current level and only ratchets up.
- **Determinism regression:** add a fixed-clock byte-identical replay assertion
  for at least one lab if not already explicit.

## 17. Release acceptance criteria

`v0.1.0` is acceptable when **all** of the following hold at the release
commit, re-run on the target platform:

1. **Version consistency:** `pyproject.toml`, `src/agentsec/__init__.py` and
   `CITATION.cff` all read `0.1.0` (`check_version.py` 3/3).
2. **Licensing:** `check_licensing.py` passes 9/9 with **0** unaccounted, 0
   conflicts, 0 stale, 0 undecided; the manifest accounts for every path.
3. **Tests:** the full suite passes (≥ the current **849**, plus tests added for
   each new behaviour), offline and hermetic.
4. **Labs:** `agentsec labs check` reports **8/8**.
5. **Docs:** `mkdocs build --strict` exits 0 with **0** warnings/errors; new
   pages are navigable and the answer key remains out of nav.
6. **Schema:** both trace-schema copies are byte-identical to a fresh
   `export_trace_schema.py` output; the packaged copy validates with no
   repository checkout beside it.
7. **Package:** the built wheel is self-contained (schema present, version
   `0.1.0`, licence MIT); install and `agentsec labs check` work from the wheel.
8. **Release gate:** `scripts/release_check.py` reports **`READY`** — or, if W12
   is retained, **`READY WITH WARNINGS`** with a **documented, explicit** warning
   set and `blockers: []` (W6 closed; W7, W9, W10, W11, W13 closed or explicitly
   re-accepted; W12 stated by decision, not by accident).
9. **CI:** both workflows are green on the release commit; pytest runs once;
   MkDocs is `PASS`, not `WARN`.
10. **Research boundary:** Phase 17 remains **CLOSED**, E1 remains **HOLD**,
    no research implementation/study/learner data exists, no novelty/
    effectiveness/benchmark/publication claim is added, and `research/20`–
    `research/38` are byte-unchanged.
11. **Repository hygiene:** the gate's hygiene check passes (no secrets,
    artefacts or tracked-ignored files); the working tree matches the release
    commit; no commit/tag/push is performed by automation.
12. **Trace of change:** the `v0.1.0` change record lists every changed file and
    the residual status of W6–W13 and R-1–R-5.
